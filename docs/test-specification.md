## 2. 테스트 범위 및 전략

### 2.1 테스트 유형

| 유형          | 설명                    | 대상                     |
| ------------- | ----------------------- | ------------------------ |
| API 테스트    | HTTP 요청/응답 검증     | 전체 엔드포인트          |
| 기능 테스트   | 화면 기반 E2E 흐름 검증 | 주요 사용자 시나리오     |
| 권한 테스트   | 역할별 접근 제어 검증   | 권한이 다른 모든 기능    |
| 유효성 테스트 | 입력 오류·경계값 검증   | 입력 폼이 있는 모든 화면 |

### 2.2 테스트 우선순위

| 우선순위  | 기준           | 해당 기능                       |
| --------- | -------------- | ------------------------------- |
| P1 (필수) | 핵심 업무 흐름 | 보고서 작성·조회, 댓글, 로그인  |
| P2 (높음) | 데이터 무결성  | 중복 방지, 삭제 제약, 권한 통제 |
| P3 (보통) | 보조 기능      | 고객·사용자 마스터 CRUD         |
| P4 (낮음) | 편의 기능      | 검색·필터, 페이지네이션         |

## 4. 공통 전제조건

별도 명시가 없는 경우 아래 조건이 적용됩니다.

- 테스트 DB는 각 테스트 케이스 실행 전 초기 상태로 리셋됩니다.
- API 테스트는 `Authorization: Bearer {token}` 헤더를 포함합니다.
- 날짜 기본값은 `2026-04-13` 입니다.
